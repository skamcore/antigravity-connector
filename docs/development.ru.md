# Архитектура и разработка

## Структура исходников

| Файл в work/connect | Назначение |
| --- | --- |
| App.cs | Точка входа, установка/откат, ярлыки, интерфейс и время жизни сеанса |
| Core.cs | Поиск прокси, транспорт, TLS-записи, ретранслятор, проверка связи, настройки и подготовка бинарных файлов |
| UI.cs | Скруглённые кнопки, карточка статуса и строки переключателей |
| I18n.cs | RU/EN-словарь и перевод динамических статусов |
| Tests.cs | Изолированные проверки файлов, сети и состояния интерфейса |
| audit/AuditRunner.cs | Консольный запуск тестов с отдельным Store.Root |
| AssemblyInfo.cs | Метаданные и версия |

Службы, расширения браузера, отдельного демона и восстановления пакетов нет. В тестах пути рабочего стола и меню «Пуск» подменены отдельными каталогами.

## Порядок запуска

1. Читаются разрешение и настройки. Повреждённые настройки означают отключённое соединение.
2. Находится Antigravity. Если процесс уже работает, открывается существующий экземпляр без изменения окружения.
3. Именованный mutex предотвращает одновременный запуск нескольких помощников в сеансе.
4. Перебираются loopback-прокси: включённый системный прокси Windows, типовые порты и слушающие порты известных VPN-ядер из netstat. Проверяется HTTP CONNECT / SOCKS5 без пароля к www.google.com:443.
5. Выбирается первый принявший запрос прокси. Иначе, если разрешено, используется распознаваемый активный TUN-адаптер.
6. Запускается IPv4 loopback-ретранслятор на выделенном ОС порту, подготавливаются совместимые бинарные файлы Antigravity.
7. Приложение получает HTTP_PROXY, HTTPS_PROXY, ALL_PROXY и варианты в нижнем регистре, AG_LS_PROXY, NO_PROXY/no_proxy и флаги прокси Chromium.
8. Ретранслятор живёт, пока остаются процессы с именем Antigravity. Затем закрываются слушатель и активные сокеты.

Проба подтверждает согласование прокси, но не полноценную TLS-связь с целевыми серверами. При установке и по кнопке проверки дополнительно вызывается Health.Check. После более поздней TLS-ошибки другой кандидат автоматически не выбирается.

## Сетевое поведение

Только CONNECT к cloudcode-pa.googleapis.com:443 и daily-cloudcode-pa.googleapis.com:443 направляется upstream к www.google.com:443. SNI клиента и зашифрованный HTTP сохраняются. Первая подходящая TLS-запись рукопожатия делится после 32 байтов полезной нагрузки; все байты сохраняются. Остальные назначения проходят обычным путём. Также реализована базовая передача незашифрованных HTTP-запросов.

Потоки передаются асинхронно в обе стороны, поддерживается TCP half-close, при ошибке закрываются оба конца. Dispose закрывает ожидающие и активные подключения. Начальные операции имеют тайм-ауты; у установленных туннелей тайм-аута чтения нет. Ограничителя числа соединений, авторизации локального клиента, kill switch и полного универсального HTTP-парсера нет. Это локальный помощник приложения, а не публичный прокси-сервер.

Health.Check использует Windows SslStream, TLS 1.2, стандартную проверку сертификата и его отзыва. Отправляет HEAD / обоим серверам Google и принимает HTTP-ответ, включая статусы вне 2xx. Это подтверждает транспортную доступность, а не доступ к модели или аккаунту.

## Хранение и изменения

Настройки и манифест записываются через временный файл с атомарной заменой. Копии ярлыков содержат исходные байты. Установка сохраняет состояние изменяемых ярлыков, манифеста и настроек, восстанавливая его при перехваченной ошибке. Это не делает устойчивым к аварии ОС весь процесс и не включает замену EXE/иконки в общую транзакцию. Отключение трогает только принадлежащие коннектору ярлыки либо восстанавливает ранее удалённые исходные.

Подготовка бинарных файлов ищет language_server.exe / agy.exe в resources, заменяет ASCII-маркеры одинаковой длины и сохраняет исходные файлы с именем по SHA-256. Замена файла атомарная. Проверка маркера — эвристика, а не список подтверждённых версий и подписей. Автоматической карты восстановления копий нет; для чистого отката рекомендуется переустановка Antigravity. Установленный экземпляр мог быть изменён другим инструментом ранее.

Корень установки приводится к физическому пути для работы с перенаправлением AppData. Настройки, манифесты ярлыков, логи, профили и копии бинарных файлов нельзя включать в публикацию.

## Сборка и тесты

Нужна 64-битная Windows и компилятор .NET Framework Windows/Microsoft.NET/Framework64/v4.0.30319/csc.exe:

```powershell
.\work\connect\build.ps1 -Audit
# Другой выходной файл:
.\work\connect\build.ps1 -Destination outputs\custom-setup.exe
```

Аудит должен завершиться кодом 0 и строкой AUDIT TESTS PASSED. Проверяются точные адреса серверов, границы и повторяемость патча, сохранность TLS-байтов, обрезанные потоки, HTTP/SOCKS, строгий разбор CONNECT, half-close, закрытие ожидающих клиентов, повреждённые настройки, восстановление ярлыков, откат неудачной установки, миграция ярлыка и сохранение RU/EN без потери несохранённых параметров. Используются локальные тестовые серверы и отдельные каталоги, VPN не требуется.

Сборки и тестовые каталоги исключены из Git. Добавлен workflow Windows CI. У CI нет пользовательского VPN и Google-входа, поэтому он не подтверждает ответ модели. Шрифт Inter при отсутствии заменяется на Segoe UI. Масштабирование и клавиатурный фокус проверяйте на целевом экране Windows.

## Командная строка

| Аргумент | Действие |
| --- | --- |
| нет / --settings | Окно настроек |
| --launch | Запуск или фокус Antigravity с сохранённой установкой |
| --check | Требует сохранённое разрешение, учитывает TUN, проверяет сеть, пишет check-result.txt только при успехе; код 0/1 |
| --refresh-shortcuts | Применяет сохранённую установку, включая обновление EXE из установщика; код 0/1 |
| --self-test | Вход для разработчика; вместо прямого вызова используйте изолированный build.ps1 -Audit |

В CLI проверяйте код завершения: старый файл успешной проверки не удаляется после новой ошибки. Логи содержат рабочие ошибки, а не полную трассировку сети.

## Выпуск версии

Обновите AssemblyInfo, историю и документацию, запустите аудит, проверьте состав файлов и diff, протестируйте интерфейс, соберите из публикуемого дерева, вычислите SHA-256 и опубликуйте EXE с контрольными суммами в релизе с тегом. Для локального обновления закройте работающий экземпляр. Подпись кода и автообновление не настроены. Пользовательские данные и дистрибутив исходного проекта в релиз не включаются.
